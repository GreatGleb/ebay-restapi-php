| Поле | Значение |
|------|----------|
| **Название проекта** | CortexParts — Интерактивный лендинг SaaS-платформы |
| **Тип сайта** | Одностраничный лендинг с интерактивным видео-фоном (scroll scrubbing) |
| **Цель** | Создать высокотехнологичный лендинг для презентации SaaS-продукта в сфере автозапчастей. Дизайн должен сочетать эстетику «инженерного минимализма» с интерактивностью. |

| Компонент | Технология |
|-----------|------------|
| **Фреймворк** | Next.js (App Router) **или** Nuxt 3 (выбор обусловлен необходимостью качественного SEO, Server-Side Rendering и быстрой загрузки контента) |

| **Хостинг** | Vercel (Next.js) / Netlify (Nuxt) |

## 3. Архитектура и функциональные требования

### 3.1. Интеграция Video-Background и контента (Эффект присутствия)

#### Концепция «Живого окружения»
Сайт использует высококачественный видеоряд, жестко синхронизированный со скроллом (Scrubbing). Видео выступает в роли «атмосферного фона» (например, плавная кинематографичная съемка процесса работы с автодеталями, абстрактные технологичные движения), создавая эффект погружения пользователя в рабочую среду SaaS-платформы.

#### Синхронизация (Scroll-to-Frame)
- Видеоряд должен быть привязан к позиции скролла через `ScrollTrigger`.
- При скролле вниз — видео движется вперед, при скролле вверх — назад.
- Это создает ощущение тотального контроля и премиального взаимодействия.

#### Приоритет читаемости и Focus Control
- **Визуальное разграничение**: Фотографии конкретных товаров и текстовые блоки (карточки с описанием, ценами) располагаются в отдельных слоях поверх видео.
- **Динамическая обработка**: В момент остановки скролла (на «станциях») видео-фон должен уходить в легкое размытие (`blur`) и снижение яркости/контрастности, чтобы внимание пользователя на 100% переключалось на контент (текст и фото товара).
- **Эффект присутствия**: Окружение не должно «отвлекать». Видео — это лишь контекстный фон, поддерживающий технологичный имидж. Вся информация (тексты, иконки, цены) должна быть четкой, контрастной и легко читаемой на фоне движущихся элементов.
- **Механика отображения**: Использование CSS-фильтров (`backdrop-filter: blur`, `opacity`, `filter: brightness`) для карточек контента, чтобы сквозь полупрозрачные фоны блоков считывалась глубина видео-сцены, но текст оставался максимально четким.

### 3.2. SEO-оптимизация

- **SSR/SSG**: Весь контент карточек должен быть доступен для поисковых роботов (индексация заголовков, описаний и характеристик).
- **Metadata**: Использование динамических мета-тегов (`title`, `description`, `Open Graph`) для каждой страницы продукта.
- **Performance**: Оптимизация шрифтов и ассетов. Google Lighthouse score — не менее 90+ по всем показателям.
- **Дополнительно**: `robots.txt`, `sitemap.xml`, JSON-LD разметка (`SoftwareApplication`, `Product`, `FAQ`).

### 3.3. Форма захвата и интеграция с Google Sheets

- **Форма**: Стандартная форма контакта (Name, Company, Email, Phone, Message).
- **Валидация**: На стороне клиента (Zod/Yup) и сервера.
- **Защита от спама**: Honeypot / Cloudflare Turnstile / reCAPTCHA v3.
- **Интеграция с Google Sheets**:
  - **Запрещена** прямая отправка с фронтенда (из соображений безопасности ключей).
  - Реализовать **API-роут на стороне сервера** (Next.js API Routes или Nuxt Server Routes), который принимает данные, валидирует их и через Google Sheets API (или вебхук через Make.com / Zapier) записывает данные в таблицу.
- **Feedback**: Реализовать UX-состояние отправки: отображение лоадера при отправке и подтверждение успеха/ошибки после завершения.

## 4. Требования к UI/UX

### 4.1. Типографика
- Использование строгих, легко читаемых шрифтов.
- Иерархия заголовков согласно структуре `inner` / `title --xlarge`.

### 4.2. Адаптивность
- Полная поддержка мобильных устройств.
- На мобильных устройствах видео-фон должен упрощаться (или отключаться) для экономии ресурсов, с приоритетом на читаемость контента и доступность формы.

### 4.3. Интерактивные элементы
- Иконки в формате SVG, стилизованные в едином ключе.
- Использование `backdrop-filter: blur` для панелей контента поверх видео.

### 4.4. Цветовая палитра

**Фирменный цвет логотипа**: `#ff6150` (оранжевый)

На сайте используется **3 основных цвета**:

| Роль | Цвет | Описание |
|------|------|----------|
| **Primary (фирменный)** | `#ff6150` | Оранжевый — цвет логотипа, используется для CTA-кнопок, акцентных элементов, ключевых заголовков |
| **Light (светлый)** | TBD | Выбор на усмотрение разработчика/дизайнера (например, `#f8fafc` или `#ffffff`) — фон, карточки, текст |
| **Dark (тёмный)** | TBD | Выбор на усмотрение разработчика/дизайнера (например, `#0f172a` или `#1e293b`) — фон секций, текст, подвалы |

> **Примечание**: Светлый и тёмный цвета выбираются дизайнером/разработчиком таким образом, чтобы обеспечить достаточный контраст и читаемость в паре с фирменным оранжевым `#ff6150`. Поскольку сайт предполагает тёмную технологичную эстетику с видео-фоном, рекомендуется использовать тёмный фон с оранжевыми акцентами.

## 5. Структура лендинга (SaaS-воронка)

Лендинг должен быть построен по классической воронке SaaS, поддерживая технологичный стиль:

### 5.1. Hero Section (Первый экран)

| Элемент | Описание |
|---------|----------|
| **Value Proposition** | Четкий заголовок о решении проблемы автоматизации eBay-листингов |
| **CTA** | Кнопка «Начать автоматизацию» или «Попробовать бесплатно» |
| **Video-фон** | Кинематографичный видеоряд, задающий тон (сцена «цеха» или «цифрового склада») |

### 5.2. Problem / Pain Points

Краткий блок о том, что ручное добавление автодеталей — это «пожиратель» ресурсов (время, деньги, ошибки). Создает эмоциональную связь с клиентом.

### 5.3. How It Works (Интерактивная часть)

Блок, раскрывающий работу через параметры:
```
Загрузка данных → Автоматизация → eBay
```

Здесь используется структура с переключаемыми карточками (интерактивные табы/аккордеон).

### 5.4. Pricing (Тарифная сетка)

Интерактивные карты тарифов с выбором пакета:

| Пакет | Цена за 1 шт. |
|-------|---------------|
| **100 товаров** | 0,75 € |
| **500 товаров** | Средняя между 0,75 € и 0,40 € |
| **1000+ товаров** | 0,40 € |

- Визуальное отображение экономии при переходе на более крупный пакет
- Понятный выбор между пакетами с подсчётом итоговой стоимости
- Акцент на выгоде: чем больше объём, тем ниже цена за единицу

### 5.5. Features / Benefits

Технические преимущества:
- Синхронизация stock-уровней
- Работа с OE-кодами
- Интеграция с Google Sheets

### 5.6. Trust & Integration

Логотипы eBay, Google Sheets (подтверждение того, с чем работает система).

### 5.7. Footer / Final CTA

Финальный призыв к действию и форма сбора лидов (Google Sheets API).
